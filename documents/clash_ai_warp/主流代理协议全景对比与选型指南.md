# 主流代理协议全景深度对比与选型指南 (含 XHTTP / AnyTLS / Reality / Hy2 / 服务端面板)

本文档针对现代主流代理协议（VLESS-Vision、VLESS-Reality、XHTTP、Hysteria2、Tuic、AnyTLS）、两大核心内核（**Xray** 与 **Sing-box**）、**全平台客户端矩阵**以及**主流服务端部署工具/面板（3X-UI vs vasma vs Marzban）**进行深度技术解析、原理对比与选型指引。

---

## 1. 什么是 XHTTP 协议？

### 1.1 背景与诞生原因
在 XHTTP 诞生之前，当我们需要隐藏服务器真实 IP（套 Cloudflare CDN / Nginx 反代）时，主流使用的是 **WebSocket+TLS** 或 **gRPC**：
- **WebSocket 的痛点**：必须先发送明显的 `Upgrade: websocket` 升级握手，特征极其明显，易被 GFW 深度包检测（DPI）识别和干扰。
- **gRPC 的痛点**：强制依赖 HTTP/2，传输长连接时有明显的 gRPC 帧头指纹，部分省份运营商已对 gRPC 实施精准丢包或限速。

为了彻底解决上述缺陷，Xray 官方团队于 2024 年推出了 **XHTTP（Xray HTTP Transport）**，作为下一代通用 HTTP 传输层标准。

---

### 1.2 XHTTP 的核心工作原理
XHTTP 将代理数据流伪装成**最标准、最普通的现代 Web HTTP 请求**（支持 HTTP/1.1、HTTP/2 及 HTTP/3）：

```text
[上行流量（上传）] ──> 伪装成标准的 HTTP POST 请求（通过流式传输 Transfer-Encoding: chunked 上传）
[下行流量（下载）] ──> 伪装成标准的 HTTP GET 响应（持续长流式 Response body 接收）
```

#### XHTTP 的四大核心优势：
1. **零特殊协议升级（Zero Upgrade）**：不发送任何 `Upgrade: websocket` 握手头，对外部检测者来说，这就是一个正常的浏览器在向网站上传和下载文件。
2. **极佳的 CDN 穿透与兼容性**：完美兼容 Cloudflare、Fastly 等所有主流 CDN 平台的默认配置，不需要 CDN 开启 WebSocket 支持即可工作。
3. **多路复用与抗断流（Packet/Stream 模式）**：
   - `auto` / `stream-up`：高性能长流模式；
   - `packet-up`：将数据切片为独立 HTTP 请求，哪怕网络偶发中断也能无感断点续传。
4. **可结合 Reality 强强联合（VLESS + Reality + XHTTP）**：既不需要自备域名证书（借用大厂证书），又具备流式 HTTP 伪装。

> **客户端要求**：需较新版本的客户端内核支持（Xray-core 1.8.11+ / Mihomo 1.18.7+）。

## 2. 核心现代代理协议全景对比

| 协议名称 | 传输层 | 核心优势 | 潜在短板 / 局限 | 推荐使用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **VLESS + TCP + TLS [Vision]** | TCP | 针对 TLS 内部双重特征消除，兼容性极好，老牌最稳 | 依赖有效域名与 SSL 证书，高延迟网络首包有握手等待 | **主力日常翻墙、长期稳定首选** |
| **VLESS + Reality [Vision]** | TCP | **免自备域名与证书**，直接借用海外大厂 SNI 伪装，防探测能力极强 | 服务端与客户端需严格对齐 Public/Private Key | **不想买域名/不想维护证书的首选** |
| **VLESS + Reality [XHTTP]** | HTTP/1.1~H3 | 伪装成纯正 Web HTTP 上传下载流量，CDN 兼容极好 | 较新协议，部分老旧客户端未支持 | **穿透企业内网防火墙、配合 CDN 防封** |
| **Hysteria 2 (Hy2)** | UDP (QUIC) | **暴力单边 BBR 拥塞控制**，弱网、高丢包、晚高峰跑满带宽 | 纯 UDP 传输，部分地区/内网会封杀或 QoS 限制 UDP | **晚高峰看 4K/8K 视频、大文件极速下载** |
| **Tuic v5** | UDP (QUIC) | 基于 QUIC 原生多路复用，0-RTT 极速握手，换网不掉线 | 同上，易受本地 UDP QoS 干扰 | **移动端（地铁/Wi-Fi频繁切换）、低延迟交互** |
| **AnyTLS** | TCP+TLS 1.3 | **0-RTT 极速首包** + 任意端口多路复用，无惧 UDP 封锁 | 社区较新，主要在 Sing-box 生态流行 | **公司/学校内网禁用 UDP 时的极速替代方案** |

## 3. Xray-core 与 Sing-box 核心技术与架构对比

### 3.1 核心定位与技术底蕴
- **Xray-core (Project X)**：
  - **定位**：专注于 **TLS 拟态伪装与高级流量对抗**。
  - **代表作**：XTLS、Vision (`xtls-rprx-vision`)、Reality、XHTTP、Splice 直通。
  - **风格**：在单项协议（TCP/TLS）上做到极致，对各种客户端的不规范握手兼容度极高。
- **Sing-box (SagerNet 团队)**：
  - **定位**：**全能通用代理平台（Universal Proxy Platform）**。
  - **代表作**：原生集成 Hysteria2、Tuic、AnyTLS、ShadowTLS、WireGuard、Binary RuleSet (.srs)。
  - **风格**：Go 语言原生现代架构，内存占用小、路由匹配飞快，全协议矩阵支持最快。

### 3.2 深度对比矩阵

| 评估维度 | Xray-core | Sing-box | 优胜分析 |
| :--- | :--- | :--- | :--- |
| **协议生态完整度** | 主打 TCP/TLS（无原生 Hy2/Tuic） | **全协议大一统**（同时支持 TCP/UDP/WireGuard） | **Sing-box 胜** |
| **UDP 弱网加速 (Hy2/Tuic)** | 不原生支持（需外挂） | **原生深度支持**，吞吐与稳定性俱佳 | **Sing-box 胜** |
| **VLESS Reality 细节** | 原创核心，容错率高、抗量子握手支持快 | 严格遵循标准规范，不容忍客户端参数瑕疵 | **Xray 兼容性微优** |
| **系统资源占用 (CPU/RAM)** | 良好（适合 1G 以上内存 VPS） | **极致轻量**（512M 小鸡轻松跑满） | **Sing-box 胜** |
| **分流规则匹配速度** | 基于传统文本列表匹配 | 基于 **.srs 二进制规则集**，毫秒级快速匹配 | **Sing-box 胜** |
| **配置生态与面板支持** | 3X-UI、v2rayN、老牌工具默认核心 | 3X-UI(新版)、Marzban、NekoBox、Karing、Shadowrocket | **平手（均已全面普及）** |

## 6. 常见网络场景下的协议选型速查表

```text
                     ┌─ 是 ──> 运营商是否封杀 UDP？ ──┬─ 否 ──> 推荐：Hysteria 2 / Tuic v5
                     │                                └─ 是 ──> 推荐：AnyTLS / VLESS-TCP-Vision
网络环境是否严重丢包？ ┤
                     │                                ┌─ 是 ──> 推荐：VLESS-Reality-Vision
                     └─ 否 ──> 是否有自备域名与证书？ ─┤
                                                      └─ 否 ──> 推荐：VLESS-TCP-TLS-Vision
```

### 场景 1：家庭宽带 / 5G 手机主力翻墙（追求综合稳定性）
- **首选**：`VLESS + TCP + TLS [Vision]` 或 `VLESS + Reality + Vision`
- **理由**：流量指纹无限接近真实 HTTPS 浏览，长年累月使用不易被封 IP。

### 场景 2：晚高峰跨国丢包严重、观看 4K/8K 视频
- **首选**：`Hysteria 2`
- **理由**：基于 UDP + 单边暴力 BBR 拥塞控制，即使链路丢包 20%~30% 依然能跑满带宽。

### 场景 3：公司内网 / 校园网限制严格（封锁 443 以外端口且封杀 UDP）
- **首选**：`VLESS + TCP + TLS [Vision]`（443 端口） 或 `AnyTLS`
- **理由**：直接伪装为标准 HTTPS 出站，穿透绝大多数内网防火墙。

### 场景 4：VPS IP 已经被 GFW 封锁 / 需套 Cloudflare CDN 救活
- **首选**：`VLESS + XHTTP`（配合 Cloudflare CDN）
- **理由**：无需 WebSocket 升级头，直接利用 CDN 传输流式 HTTP，速度优于传统 WS+CDN。
